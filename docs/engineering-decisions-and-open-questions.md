## 2. Политика конфиденциальности: зачем **текст** и **URL** (SR-PRIV-5)

Вопрос из реестра: «зачем нужен текст и URL?»

- **URL** — ссылка, которую пользователь может открыть из приложения и с сайта. Требование **SR-PRIV-5** и ожидания модерации стора: политика должна быть **доступна по постоянному адресу**, без «магии» только внутри APK.
- **Текст** — сам документ политики (юридический смысл). Одна ссылка без согласованного текста недостаточна: нужен **согласованный с юристом** материал, описывающий Firebase/GA4 и фактический состав SDK, как в СТ.

Итог: **URL** = место публикации; **текст** = содержание. Оба участвуют в приёмке; срок и формулировки — вне инженерного объёма, но **блокер релиза** остаётся продуктово-юридическим.

## 3. Предложение бизнесу: вместо отдельной CMS (историческая справка)

Ранее рассматривались кастомная админка и low-code. **Текущее решение по ED-4:** на ранних этапах **нет отдельной админки** — контент ведётся через **файлы + импорт** (см. skill/rule). По мере роста продукта возможен переход на варианты **A/B** из нижней таблицы без смены модели данных в Firestore.

| Вариант | Суть | Когда |
|---------|------|--------|
| **A. Кастомная веб-админка** | Next.js или отдельный фронт, Firebase Admin SDK | После появления бюджета на E1+ |
| **B. Low-code над Firestore** | Retool / аналог | Быстрый UI для эксперта без полной разработки |
| **Текущее (ED-4)** | Cursor + JSON/скрипты импорта | До инвестиций в админку |

## 6. Реестр вопросов (закрытые и открытые)

### Закрыто (решения зафиксированы выше или в §2 про политику)

1. Хостинг статики — **GitHub Pages** (**ED-3**).
2. Админка на старте — **нет**, импорт через Cursor + скрипты (**ED-4**).
3. Роли — **один эксперт, минимально** (**ED-5**).
4. Библиотеки Flutter — **индустриальные нормы + решение tech lead** (**ED-6, ED-13**).
5. Загрузка картинок — **прямой upload** (**ED-7**).
6. Slug — **из заголовка + уникальность** (**ED-8**).
7. Страница игры при нескольких сценариях — **текст обязателен, без дефолта** (**ED-9**).
8. Next.js — **полный rebuild по ручному триггеру** (**ED-10**).
9. Тексты push — **поля в Firestore** (**ED-11**).
10. KPI пороги — **на будущее** (**ED-12**).
11. Зачем текст и URL политики — см. **[§2](#2-политика-конфиденциальности-зачем-текст-и-url-sr-priv-5)**.

### Открыто (tech lead / команда)

12. **Точные имена коллекций и полей** публичных агрегатов и правило миграции схемы — **ADR-010**, реализация.
13. **Лимиты размера/формата изображений** на входе пайплайна импорта — зафиксировать в гайдлайне контента / скрипте.
14. **Детальный выбор пакетов Flutter** — **ED-13**, ADR-004–009. **Закрыто (кэш изображений):** `cached_network_image` 4.x, лимит по числу объектов — см. ADR-004–009.
