# Именованная схема событий аналитики в МП

## Ценность

Единая схема имён событий в GA4 (или выбранном инструменте) позволяет строить отчёты и KPI без хаоса в данных (**FR-M-6**, **BR-7**, **СТ A-35**).

## Контекст и трассировка

| ID | Документ | Как используется в этой стори |
|----|----------|-------------------------------|
| FR-M-6 | БТ | События навигации и контента |
| A-35 | СТ | Именованная схема событий |
| ED-14 | ED | ADR по именам событий |

## Детали поведения

- Документ/таблица с перечнем событий и параметров (согласно **A-35**).
- Клиент отправляет события при ключевых переходах (витрина, сценарий, игра — базовый набор).
- Согласование с **ED-14** (ADR).

## Вне scope

- Детальные `source` для сценария — **US-E6-02**; block_view — **US-E6-03**.

## Критерии приёмки (AC)

- **AC-01** *(СТ A-35)*  
  - Given согласованная схема  
  - When разработчик добавляет событие  
  - Then имя и параметры входят в реестр, без произвольных строк.

- **AC-02** *(БТ FR-M-6)*  
  - Given типичная сессия  
  - When пользователь переходит по основным экранам  
  - Then в аналитику попадают соответствующие события.

## Зависимости и блокеры

- Интеграция GA4/Firebase Analytics по проекту.
