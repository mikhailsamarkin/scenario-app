# Экран игры: карусель, характеристики, краткое описание в контексте сценария

## Ценность

Экран игры даёт достаточно сигналов для решения «подходит / нет» в рамках выбранного сценария (**FR-M-2**, **CR-4.1**, **CR-5**).

## Контекст и трассировка

| ID | Документ | Как используется в этой стори |
|----|----------|-------------------------------|
| FR-M-2 | БТ | Карусель, 4 характеристики, краткое описание в контексте сценария |
| CR-4.1, CR-5 | БТ | Enum и карусель в данных |

## Детали поведения

- Карусель отображает слайды согласно типам и порядку из данных игры.
- Четыре характеристики — из допустимых enum (**CR-4.1**).
- `shortDescription` показывается в контексте связки сценарий–игра (**E1**).

## Вне scope

- Оптимизация производительности карусели — **US-E2-06**.

## Критерии приёмки (AC)

- **AC-01** *(БТ FR-M-2, CR-5)*  
  - Given открыта игра из сценария  
  - When отображается экран  
  - Then видна карусель с валидными типами слайдов и alt где задано.

- **AC-02** *(БТ CR-4.1)*  
  - Given enum-характеристики  
  - When рендер  
  - Then отображаются четыре характеристики из контракта.

- **AC-03** *(БТ FR-M-2)*  
  - Given `shortDescription` для пары сценарий–игра  
  - When экран игры открыт из этого сценария  
  - Then показывается соответствующее краткое описание.

## Зависимости и блокеры

- Публичные данные игры и связки (**E1**).

## Открытые вопросы

- Нет.

## Примечания для downstream

- Не подставлять описание из другого сценария (**ED-9** на стороне данных).
