# Не больше одного push в сутки в 11:00 МСК

## Ценность

Ограничение частоты и времени снижает раздражение и соответствует продуктовой политике «один пуш в сутки / последний сценарий» (**СТ A-7a, A-32**).

## Контекст и трассировка

| ID | Документ | Как используется в этой стори |
|----|----------|-------------------------------|
| FR-M-4 | БТ | Уведомление о новинке |
| A-7a, A-32 | СТ | Время 11:00 МСК, одно сообщение на topic при нескольких новинках |
| SR-PUSH-1 | СТ | Ограничения push |
| ED-11 | ED | Тексты в Firestore/конфиге |

## Детали поведения

- Cloud Scheduler (или аналог) запускает отправку в 11:00 МСК.
- На topic уходит не более одного сообщения в сутки; при нескольких новых сценариях — последний (**A-32**).
- Payload ссылается на сценарий для deep link (**US-E3-04**).

## Вне scope

- **Минимальный первый релиз без push** — полная приёмка откладывается до включения продукта push.

## Критерии приёмки (AC)

- **AC-01** *(СТ A-7a)*  
  - Given накопились события новых сценариев за сутки  
  - When срабатывает окно 11:00 МСК  
  - Then отправляется не более одного сообщения на topic за календарные сутки.

- **AC-02** *(СТ A-32)*  
  - Given несколько новинок за сутки  
  - When формируется сообщение  
  - Then в уведомлении — последний опубликованный сценарий (по политике **use-cases**).

- **AC-03** *(ED-11)*  
  - Given текст уведомления  
  - When формируется payload  
  - Then заголовок/тело могут браться из данных/конфига, не только из хардкода.
