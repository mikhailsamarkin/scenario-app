# Применение flutter-improving-accessibility (flutter/agent-plugins): доступность экранов МП

## Ценность

Доступность (a11y) сейчас не покрыта ни одной стори, хотя у Scenario есть все предпосылки: изображения слайдов карусели с `alt` (**CR-5**), чипсы характеристик, карусели, кнопки «Поделиться»/навигации. Требования по адаптивности и ориентирам Apple HIG (**A-47**, **NFR-SR-7**) включают раздел про доступность.

Официальный skill **`flutter-improving-accessibility`** (repo `flutter/agent-plugins`) даёт конкретные критерии и приёмы: масштабирование системного шрифта (без фиксированных высот текста), контраст (≥ 4.5:1 для мелкого, ≥ 3:1 для крупного текста), tap targets не меньше 48×48, работа с semantics-деревом через accessibility-виджеты (`Semantics`, `ExcludeSemantics`, `MergeSemantics`) для TalkBack/VoiceOver, а также web/adaptive-раздел.

> ⚠️ В текущем `main` `flutter/agent-plugins` файла skill нет (raw 404) — на skills.sh есть снапшот. Перед стартом подтвердить установку; при необходимости завендорить снапшот/зафиксировать коммит.

## Детали поведения

- Запустить skill и следовать его инструкциям:
  ```bash
  npx skills use "https://github.com/flutter/agent-plugins" --skill "flutter-improving-accessibility"
  ```
- **Прочитать полный вывод скилла** (при необходимости сначала перенаправить его в временный файл).
- **Относительные пути резолвить от каталога supporting-files**, который вернёт скилл (а не от корня проекта).
- Применить к ключевым экранам (главная/витрина, сценарий, игра, онбординг):
  - **Font scaling:** не фиксировать высоты текстовых контейнеров; проверять при максимальном размере системного шрифта (нет обрезания/overflow).
  - **Контраст:** ≥ 4.5:1 для мелкого и ≥ 3:1 для крупного текста; сверить с токенами **SP-E9-01**.
  - **Tap targets:** не меньше 48×48 для чипсов, иконок и кнопок.
  - **Semantics:** осмысленные labels для изображений слайдов (из `alt`, **CR-5**) и чипсов характеристик; корректный порядок фокуса в карусели; `ExcludeSemantics`/`MergeSemantics` для декоративных и составных элементов.
  - Проверка TalkBack (Android) и VoiceOver (iOS) на ключевых экранах.
- Где возможно — закрепить проверки в тестах (`WidgetTester` + semantics-матчеры: labels/actions).
- **Поведение и контент не меняются:** правки касаются доступности, не продуктовых сценариев.

## Вне scope

- Локализация/перевод интерфейса (отдельная тема).
- Изменение визуального дизайна вне критериев a11y.
- Аудит сайта `scenario-site/` (a11y веба — вне этой стори, кроме общей ориентировки).

## Критерии приёмки (AC)

- **AC-01**
  - Given репозиторий `scenario`
  - When выполнен запуск `npx skills use "https://github.com/flutter/agent-plugins" --skill "flutter-improving-accessibility"` (или зафиксирован снапшот) и прочитан его полный вывод
  - Then инструкции применены, относительные пути резолвятся от supporting-files.

- **AC-02**
  - Given ключевые экраны МП
  - When включены максимальный системный размер шрифта и скринридер
  - Then текст не обрезается и не переполняет layout, кнопки/чипсы достигаемы (≥ 48×48), изображения и характеристики озвучиваются, контраст соответствует нормам скилла.

- **AC-03**
  - Given внесённые изменения
  - When запущены `flutter analyze` и `flutter test`
  - Then ошибок нет, тесты зелёные; для ключевых компонентов добавлены semantics-проверки.

## Зависимости и блокеры

- Доступ в сеть для `npx skills use`; Flutter SDK.
- Устройства/симуляторы с TalkBack и VoiceOver для ручной проверки.
- **Продуктовое согласие:** явных a11y-требований в БТ/СТ нет — опираемся на **A-47/CR-5/NFR-SR-7** и критерии скилла; иначе риск формального подхода.
- Доступность самого skill (в `main` отсутствует) — завендорить снапшот.
