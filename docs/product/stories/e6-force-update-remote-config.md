# Принудительное обновление через Remote Config

## Ценность

Устаревшие клиенты не получают сломанный UX при смене схемы контента или критичных API (**СТ A-45**).

## Контекст и трассировка

| ID | Документ | Как используется в этой стори |
|----|----------|-------------------------------|
| A-45 | СТ | `min_supported_build`, `content_schema_version`, Remote Config |
| ADR-013 | ED | Версия схемы контента и RC |

## Детали поведения

- Remote Config содержит минимально поддерживаемый номер сборки и/или версию схемы контента.
- Клиент сравнивает с локальными значениями; при несовместимости показывает экран обновления и блокирует основной поток.
- Политика текста и ссылок на сторы — продукт/дизайн.

## Вне scope

- Серверное принуждение вне клиента.

## Критерии приёмки (AC)

- **AC-01** *(СТ A-45)*  
  - Given Remote Config с `min_supported_build` выше текущей сборки  
  - When приложение стартует  
  - Then пользователь видит требование обновления и не может обойти его для основного контента.

- **AC-02**  
  - Given повышение `content_schema_version` в данных  
  - When клиент не поддерживает версию  
  - Then срабатывает та же или согласованная ветка обновления.

## Зависимости и блокеры

- Firebase Remote Config, публикация параметров.

## Открытые вопросы

- Нет.

## Примечания для downstream

- Согласовать с **E0** при изменении контракта.
