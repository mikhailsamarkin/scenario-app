# Окружения Firebase dev/staging и production

## Ценность

Разделение окружений снижает риск порчи продакшен-данных и даёт предсказуемую проверку публикации и клиентов до релиза.

## Контекст и трассировка

| ID | Документ | Как используется в этой стори |
|----|----------|-------------------------------|
| A-43 | СТ | Два (или более) окружения Firebase |
| A-40 | СТ | Секреты и ключи не хранятся в репозитории |

## Детали поведения

- Настроены как минимум dev/staging и production (или эквивалент по **A-43**).
- Конфигурация клиентов и CI использует переменные окружения / секреты вне git (**A-40**).
- Документировать, какой проект для какой ветки/сборки (кратко, для команды).

## Вне scope

- Полный CI/CD всех каналов — в рамках отдельных задач, если не требуется для приёмки окружений.

## Критерии приёмки (AC)

- **AC-01** *(СТ A-43)*  
  - Given необходимость тестирования без влияния на прод  
  - When команда выполняет публикацию или запускает клиент  
  - Then существует отдельное окружение(я) от production согласно политике **A-43**.

- **AC-02** *(СТ A-40)*  
  - Given репозиторий с кодом и скриптами  
  - When проверяется хранение секретов  
  - Then ключи сервисных аккаунтов и прочие секреты не коммитятся в git.

## Зависимости и блокеры

- Учётные записи и права в Google Cloud / Firebase для создания проектов.

## Открытые вопросы

- Нет.
