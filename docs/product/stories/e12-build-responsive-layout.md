# Применение flutter-build-responsive-layout: адаптивная вёрстка экранов МП

## Ценность

Сейчас макет МП ориентирован на узкий экран телефона: полноширинные списки, карусели и текстовые блоки на планшетах и десктопных окнах выглядят растянуто, а ломающие layout ошибки (`RenderFlex overflowed`, `unbounded height`) не покрыты проверками. Эта стори применяет официальный skill Flutter **`flutter-build-responsive-layout`** и делает UI адаптивным к доступному пространству окна, а не к типу устройства.

## Детали поведения

- Запустить skill и следовать его инструкциям:
  ```bash
  npx skills use "https://github.com/flutter/agent-plugins" --skill "flutter-build-responsive-layout"
  ```
- **Прочитать полный вывод скилла** (при необходимости сначала перенаправить его в временный файл).
- **Относительные пути резолвить от каталога supporting-files**, который вернёт скилл (а не от корня проекта).
- Применить рекомендованные приёмы:
  - `LayoutBuilder` для решений по `constraints.maxWidth`; `MediaQuery.sizeOf(context)` для размера окна приложения; **не** использовать `MediaQuery.orientationOf`/`OrientationBuilder` в верхней части дерева и не определять тип железа.
  - `Expanded`/`Flexible` в `Row`/`Column`/`Flex` для распределения пространства.
  - Ограничение ширины на больших экранах: `ConstrainedBox(maxWidth: …)` + `Center` для текста/форм; для списков — `GridView.builder` со `SliverGridDelegateWithMaxCrossAxisExtent`.
  - Ленивый рендер: `ListView.builder`/`GridView.builder` для длинных списков.
  - Не блокировать ориентацию экрана.
- Определить единый брейкпоинт (например, `largeScreenMinWidth = 600`) и вынести его в дизайн-систему/`lib/design`.
- **Поведение и контент не меняются:** навигация и данные остаются прежними, меняется только раскладка.
- После изменений запустить `flutter analyze` и `flutter test`; проверить layout на нескольких размерах окна/поворотах.

## Вне scope

- Изменение контента, данных и навигации.
- Отдельная настольная/веб-версия приложения и поддержка мыши/клавиатуры сверх базовой.
- Рефакторинг архитектуры (см. US-E12-01, US-E12-03).

## Критерии приёмки (AC)

- **AC-01**
  - Given репозиторий `scenario`
  - When выполнен запуск `npx skills use "https://github.com/flutter/agent-plugins" --skill "flutter-build-responsive-layout"` и прочитан его полный вывод
  - Then инструкции скилла применены, относительные пути резолвятся от supporting-files.

- **AC-02**
  - Given экраны МП (главная, сценарий, игра, онбординг)
  - When окно изменяется от узкого к широкому и меняется ориентация
  - Then раскладка адаптируется (брейкпоинт), контент на больших экранах не растягивается на всю ширину, overflow отсутствует.

- **AC-03**
  - Given внесённые изменения
  - When запущены `flutter analyze` и `flutter test`
  - Then ошибок нет, тесты зелёные, поведение не изменилось.

## Зависимости и блокеры

- Доступ в сеть для `npx skills use` (загрузка скилла с `github.com`).
- Node.js/npx в окружении разработчика.
- Область широкая (все экраны): вести инкрементально, по экранам.

## Открытые вопросы

- Достаточно ли поддержки телефона/планшета или нужен полноценный десктопный layout (сайдбар и т.п.)?
- Где хранить брейкпоинты — в `lib/design` или отдельном модуле адаптива?

## Примечания для downstream

- После правок прогнать `flutter analyze`/`flutter test`; визуально проверить на нескольких размерах окна и в ландшафте.
- При появлении виджет-тестов на overflow — учитывать новую адаптивную логику.
