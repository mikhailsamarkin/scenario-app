# Онбординг: ценность «ситуация → игры»

## Ценность

Первый запуск объясняет ценность продукта и снижает трение до первого ценного действия (**UJ-4**); отказ от push не блокирует доступ к контенту (**use-cases** E3).

## Контекст и трассировка

| ID | Документ | Как используется в этой стори |
|----|----------|-------------------------------|
| UJ-4 | БТ | Онбординг первого запуска |
| FR-M-3 | БТ | Первая загрузка контента / сообщение при офлайне |
| A-17 | СТ | Поведение первого запуска (по трассировке UC-06) |
| UC-06 | use-cases | Установка → онбординг → контент |

## Детали поведения

- Короткий поток экранов (или эквивалент) с объяснением модели «ситуация → игры».
- После онбординга — загрузка контента или понятное состояние при офлайне (**FR-M-3**).
- Запрос push **опционален**; отказ не блокирует переход к витрине (**use-cases** шапка: минимальный релиз без обязательного push).

## Вне scope

- Обязательная подписка на topic (**US-E3-02**) — отдельно.
- Полная реализация дневных пушей (**US-E3-03**).

## Критерии приёмки (AC)

- **AC-01** *(БТ UJ-4)*  
  - Given первый запуск после установки  
  - When пользователь проходит онбординг  
  - Then понятна связь «ситуация → подборка игр».

- **AC-02**  
  - Given пользователь отклонил push на шаге запроса  
  - When онбординг завершён  
  - Then доступ к контенту/витрине не заблокирован.
