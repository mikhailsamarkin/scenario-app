# Обновление контента при наличии сети

## Ценность

Актуальные подборки без необходимости вручную «сбрасывать» приложение; при этом не показывать пустой экран, если кэш уже есть (**FR-M-3**).

## Контекст и трассировка

| ID | Документ | Как используется в этой стори |
|----|----------|-------------------------------|
| FR-M-3 | БТ | Синхронизация и поведение при сети |
| A-20–A-22 | СТ | Persistence, обновление кэша Firestore |

## Детали поведения

- При активной сети приложение запрашивает/получает обновления документов согласно стратегии кэша (**A-20** и след.).
- Если данные уже в кэше, фоновое обновление не оставляет пользователя перед пустым экраном из-за временной задержки (**FR-M-3** по смыслу use-cases).

## Вне scope

- Полная офлайн-логика — **US-E2-05**.

## Критерии приёмки (AC)

- **AC-01** *(БТ FR-M-3)*  
  - Given сеть доступна и есть кэш  
  - When пользователь открывает приложение  
  - Then контент отображается из кэша при необходимости, обновление подтягивается без «пустого» главного экрана.

- **AC-02** *(СТ A-20)*  
  - Given новая версия опубликованного документа  
  - When клиент синхронизируется  
  - Then пользователь в конечном счёте видит актуальные данные после обновления.

## Зависимости и блокеры

- Включённый persistence Firestore (**NFR-SR-3** / **A-20** в связке с **US-E2-05**).
