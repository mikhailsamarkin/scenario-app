# Открытия сценария с разбивкой по source и scenario_id

## Ценность

Понимание источника открытия (витрина, push, share и т.д.) нужно для продуктовых решений и ранжирования (**FR-M-6**, **BR-7**).

## Контекст и трассировка

| ID | Документ | Как используется в этой стори |
|----|----------|-------------------------------|
| FR-M-6 | БТ | Открытия сценария с `source` и идентификатором |
| use-cases §6.2 | use-cases | Источники: home, group, past, push, deeplink, share |

## Детали поведения

- Событие открытия сценария содержит `scenario_id` и `source` из согласованного enum.
- Для первого релиза актуальны реализованные источники (например home; push/share — по мере появления каналов) — **use-cases** §6.2 п.9–12.

## Вне scope

- Источники, не реализованные в релизе (group, past — **E7**), помечаются как неприменимые до появления UI.

## Критерии приёмки (AC)

- **AC-01** *(БТ FR-M-6)*  
  - Given переход на сценарий с витрины  
  - When экран открыт  
  - Then событие содержит `scenario_id` и `source=home` (или согласованный ключ).

- **AC-02**  
  - Given переход из push (когда E3 включён)  
  - When экран открыт  
  - Then `source` отражает push.

## Зависимости и блокеры

- **US-E6-01** схема имён.
- Навигация **E2**, push **E3**, share **E5**.

## Открытые вопросы

- Нет.

## Примечания для downstream

- Не слать произвольные строки в `source` — только реестр.
