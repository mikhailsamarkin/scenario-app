# Офлайн: открытие ранее загруженного контента

## Ценность

Пользователь не блокируется при обрыве сети: уже загруженные сценарии и игры остаются доступны (**FR-M-3**, **UC-07**).

## Контекст и трассировка

| ID | Документ | Как используется в этой стори |
|----|----------|-------------------------------|
| FR-M-3 | БТ | Офлайн-доступ к загруженному |
| A-20–A-22 | СТ | Persistence и офлайн-поведение |
| NFR-SR-3 | СТ | Надёжность при офлайне (в **use-cases**) |

## Детали поведения

- Firestore persistence включён; чтение из локального кэша при недоступности сети.
- Изображения: см. кэш диска **US-E2-06** / **A-21a**.
- Не показывать блокирующую ошибку там, где данные есть в кэше (**UC-07**).

## Вне scope

- Полный offline-first для контента, никогда не открывавшегося онлайн (ожидаемо ограничено первым запуском).

## Критерии приёмки (AC)

- **AC-01** *(БТ FR-M-3, СТ NFR-SR-3)*  
  - Given контент был загружен при наличии сети  
  - When сеть недоступна  
  - Then пользователь открывает витрину/сценарий/игру из кэша без фатальной ошибки.

- **AC-02**  
  - Given первый запуск без сети и пустой кэш  
  - When пользователь открывает приложение  
  - Then показывается понятное состояние «нет данных / нет сети» (без противоречия **FR-M-3** — уточнить копирайт в дизайне).

## Зависимости и блокеры

- Настройка persistence (**A-20**).

## Открытые вопросы

- Точная копия для empty state при первом запуске офлайн — продукт/дизайн.

## Примечания для downstream

- Образцовый сценарий офлайн для приёмки упомянут в **use-cases** US-E2-05.
