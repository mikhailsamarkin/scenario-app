# Поля шаринга и SEO для сценария и игры

## Ценность

Единые метаданные в данных позволяют строить превью шаринга, OG и SEO-страницы без хардкода в клиентах (**FR-M-7**, **FR-W-2**).

## Контекст и трассировка

| ID | Документ | Как используется в этой стори |
|----|----------|-------------------------------|
| FR-M-7, FR-W-2 | БТ | Шаринг и поисковые метаданные |
| СТ §4.4 | СТ | Поля для SSG и share (по ссылке в **use-cases**) |
| ED-8 | ED | Slug/ЧПУ из заголовка, уникальность |
| ED-9 | ED | Страница игры: обязательные описания/SEO без «чужого» fallback |

## Детали поведения

- В данных присутствуют поля для title, description, OG-изображения (и slug при необходимости) в объёме **СТ §4.4**.
- Значения доступны для генерации ссылок и статических страниц (**FR-W-2**).
- Для игры соблюдается **ED-9**: нет пустого fallback с подстановкой текста из другого сценария.

## Вне scope

- **Минимальный первый релиз без публичного сайта** (**use-cases** шапка и §6.1): ценность SEO/OG для веба ниже; сторя готовит данные для будущих E4/E5 или может быть запланирована отдельно по бэклогу (**use-cases §7** US-E1-04).

- Полная реализация Universal Links и SSG.

## Критерии приёмки (AC)

- **AC-01** *(СТ §4.4, БТ FR-M-7, FR-W-2)*  
  - Given опубликованные сценарий и/или игра  
  - When клиент или билд читает публичные поля  
  - Then title/description/OG заданы в контракте и читаются из данных.

- **AC-02** *(ED-8)*  
  - Given новый slug  
  - When сохранение  
  - Then уникальность проверяется до публикации.

- **AC-03** *(ED-9)*  
  - Given страница игры  
  - When несколько сценариев ссылаются на игру  
  - Then нет автоподстановки описания из «другого» сценария; обязательные поля заполнены.

## Зависимости и блокеры

- Схема документов (**E0**).
- Для end-to-end шаринга — E5 и домен (**СТ A-23–A-25**).
