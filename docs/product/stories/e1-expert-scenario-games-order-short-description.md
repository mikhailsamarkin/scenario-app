# Привязка игр к сценарию: порядок и shortDescription

## Ценность

Пользователь видит подборку в заданном порядке и краткое описание игры в контексте сценария — как требует **FR-M-2**.

## Контекст и трассировка

| ID | Документ | Как используется в этой стори |
|----|----------|-------------------------------|
| FR-B-1, CR-4 | БТ | Связь сценарий–игры |
| FR-M-2 | БТ | Отображение списка игр и описания в контексте сценария |
| A-10 | СТ | Денормализация для чтения клиентом |
| ED-4 | ED | Импорт без админки |

## Детали поведения

- Для каждой игры в составе сценария задаётся порядок.
- `shortDescription` в контексте связки сценарий–игра сохраняется и попадает в публичное представление для МП (**A-10**).
- Данные согласованы с контрактом **E0** (имена полей по **СТ §4**).

## Вне scope

- UI МП (E2) — здесь только данные и публикация.

## Критерии приёмки (AC)

- **AC-01** *(БТ FR-M-2, СТ A-10)*  
  - Given сценарий и несколько игр  
  - When эксперт задаёт порядок и `shortDescription`  
  - Then публичный документ/агрегат отражает порядок и тексты для чтения МП.

- **AC-02**  
  - Given повторная публикация  
  - When меняется только порядок или описание  
  - Then обновления доступны клиенту согласно политике кэша/синхронизации (без противоречия **FR-M-3** на стороне клиента — см. E2).

## Зависимости и блокеры

- Существующие документы игры и сценария (**US-E1-01**, **US-E1-02**).
- Схема денормализации (**A-10**).

## Открытые вопросы

- Нет.

## Примечания для downstream

- `shortDescription` — plain text там, где применимо **A-4a**.
