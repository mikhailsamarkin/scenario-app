# Подписка на уведомления о новых сценариях

## Ценность

Пользователь получает реактивацию через FCM topic при согласии на уведомления (**FR-M-4**, **A-8a**).

## Контекст и трассировка

| ID | Документ | Как используется в этой стори |
|----|----------|-------------------------------|
| FR-M-4 | БТ | Push о новых сценариях |
| A-8a | СТ | Подписка на topic |
| SR-PUSH-1 | СТ | Политика push |

## Детали поведения

- После выдачи разрешения на уведомления клиент вызывает `subscribeToTopic('new_scenarios')` (или имя по **СТ**).
- Без разрешения подписка не выполняется; UX не ломает основной поток (**use-cases**).

## Вне scope

- **Минимальный первый релиз без push** (**use-cases** §6.1): реализация может быть отложена; при срезе «только онбординг» — не входит в обязательный scope.

- Scheduler и дневная отправка — **US-E3-03**.

## Критерии приёмки (AC)

- **AC-01** *(СТ A-8a, SR-PUSH-1)*  
  - Given пользователь разрешил уведомления  
  - When завершён flow подписки  
  - Then клиент подписан на topic новых сценариев.

- **AC-02**  
  - Given разрешение не выдано  
  - When приложение работает  
  - Then подписка на topic не выполняется.

## Зависимости и блокеры

- FCM настроен в проекте.
- **US-E1-05** для очереди событий публикации.

## Открытые вопросы

- Нет.

## Примечания для downstream

- Имя topic сверить с **СТ** / iOS/Android конфигурацией.
