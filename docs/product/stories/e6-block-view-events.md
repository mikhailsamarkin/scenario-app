# События block_view с порогом viewport

## Ценность

Доли пользователей, дошедших до конкретных блоков, помогают проверять гипотезы о прочтении и структуре экранов (**FR-M-6**, **СТ A-36**).

## Контекст и трассировка

| ID | Документ | Как используется в этой стори |
|----|----------|-------------------------------|
| FR-M-6 | БТ | Достижение блоков |
| A-36 | СТ | ≥50% площади, ≥300 ms, одно на блок за сессию экрана |

## Детали поведения

- Для именованных блоков на экранах сценария и игры отправляется `block_view` при выполнении порога **A-36**.
- Одно срабатывание на блок за «сессию экрана» (по **СТ**).
- Идентификаторы блоков стабильны и согласованы с дизайном/контрактом.

## Вне scope

- Heatmaps сторонних SDK.

## Критерии приёмки (AC)

- **AC-01** *(СТ A-36)*  
  - Given блок частично виден  
  - When видимая площадь ≥50% и удержание ≥300 ms  
  - Then отправляется одно событие для этого блока.

- **AC-02**  
  - Given пользователь скроллит туда-обратно  
  - When повторно попадает в блок  
  - Then повторного события за ту же сессию экрана нет.

## Зависимости и блокеры

- **US-E6-01** схема событий.
- Разметка блоков на **E2**.

## Открытые вопросы

- Нет.

## Примечания для downstream

- Список `block_id` зафиксировать рядом со схемой **A-35**.
