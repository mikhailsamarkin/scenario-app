# Сценарий с «почему эти игры подходят» и витриной

## Ценность

Сценарий задаёт смысловой контекст подборки и порядок на витрине; корректные обязательные поля и plain text обеспечивают стабильный UX в МП.

## Контекст и трассировка

| ID | Документ | Как используется в этой стори |
|----|----------|-------------------------------|
| FR-B-1, CR-4 | БТ | Сценарий, связи, контентные требования |
| A-4a | СТ | Plain text, переносы строк для клиентских текстов |
| A-4b | СТ | Согласованные ограничения форматирования при необходимости |
| ED-4 | ED | Ввод через репозиторий/скрипты |

## Детали поведения

- Поле `whyTheseGames` обязательно для операции publish (как в **use-cases** и **БТ**).
- Текст — plain text с поддержкой `\n` (**A-4a**).
- Признаки витрины и порядок отображения на главном экране задаются данными сценария/агрегатов (**FR-B-1**, **CR-4**).

## Вне scope

- Группы смысла и «Сценарии прошлого» (E7, вне минимального релиза по шапке **use-cases**).

## Критерии приёмки (AC)

- **AC-01** *(БТ FR-B-1, CR-4; СТ A-4a)*  
  - Given сценарий готовится к публикации  
  - When выполняется publish  
  - Then `whyTheseGames` заполнен и сохранён как plain text с корректными переносами.

- **AC-02** *(БТ FR-B-1)*  
  - Given настроены признаки витрины и порядок  
  - When формируется `home_feed` / публичный агрегат  
  - Then главный экран МП может построить список без релиза приложения.

## Зависимости и блокеры

- Публичная схема и агрегат витрины (**E0**).

## Открытые вопросы

- Нет.

## Примечания для downstream

- Не вставлять HTML в клиентские поля, если **A-4a** требует plain text.
