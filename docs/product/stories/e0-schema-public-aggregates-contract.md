# Схема коллекций и публичных агрегатов для единого контракта МП и Next.js

## Ценность

Один согласованный контракт данных снижает расхождения между клиентами и позволяет безопасно публиковать только «вьюхи» для чтения, скрывая черновики от публичных read-операций.

## Контекст и трассировка

| ID | Документ | Как используется в этой стори |
|----|----------|-------------------------------|
| A-10 | СТ | Денормализация, агрегаты для чтения клиентами |
| A-11 | СТ | Индексы и структура запросов под схему |
| A-12 | СТ | Контракт чтения для мобильного клиента |
| A-38 | СТ | Черновики недоступны клиентским read; публичные представления |

## Детали поведения

- Зафиксировать имена коллекций/документов публичных агрегатов (в т.ч. `*_public`, `home_feed` — по **СТ §4** и связанным A-*).
- Описать поля и связи на уровне контракта (без выдуманных полей; сверка с **СТ §4**).
- Security Rules: публичный read только к опубликованным/публичным путям; черновики не читаются клиентами (**A-38**).
- Документ схемы — единая точка согласования для МП и SSG.

## Вне scope

- Полная реализация Next.js SSG (эпик E4).
- Бизнес-логика импорта контента (E1) — кроме требований к форме данных под эту схему.

## Критерии приёмки (AC)

- **AC-01** *(СТ A-38)*  
  - Given черновик сценария/игры без публикации  
  - When клиент с публичными правами запрашивает данные  
  - Then черновик недоступен для read так же, как описано в правилах.

- **AC-02** *(СТ A-10, A-12)*  
  - Given согласованный документ схемы  
  - When разработчик МП или SSG читает публичные агрегаты  
  - Then имена коллекций/полей и семантика совпадают с документом и **СТ §4**.

- **AC-03**  
  - Given необходимость витрины и сценариев  
  - When описан `home_feed` (или эквивалент по СТ)  
  - Then структура позволяет МП построить главный экран без дополнительных недокументированных полей.

## Зависимости и блокеры

- Доступ к проекту Firebase и правам на правила безопасности.
- Согласование с **СТ** по именованию агрегатов (ADR по Firestore — **engineering-decisions** §5).

## Открытые вопросы

- При необходимости разбиения на подзадачи (схема vs правила vs агрегаты для МП) — уточнить у tech lead согласно **use-cases §7** для US-E0-01.

## Примечания для downstream

- Не дублировать полный **СТ**; при реализации импорта ссылаться на зафиксированные имена и `published`/публичные вьюхи.
