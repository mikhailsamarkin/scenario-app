# Тест-кейсы: Привязка игр к сценарию: порядок и shortDescription

## Обзор

- Цель: проверить, что порядок игр и `shortDescription` для пары сценарий–игра попадают в публичный агрегат и обновляются при повторной публикации.
- Вне scope: UI МП (E2).

## Матрица трассировки AC → тест-кейсы

| AC    | TC-ID        | Кратко |
|-------|--------------|--------|
| AC-01 | TC-01, TC-02 | Порядок и shortDescription в публичных данных |
| AC-02 | TC-03        | Обновление только порядка/описания доступно клиенту |

## Тест-кейсы

### TC-01 — Порядок игр в публичном агрегате совпадает с заданным

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-01 |
| **Тип** | positive |

**Предусловия:** Сценарий с ≥2 играми; задан явный порядок (1, 2, 3…).

**Тестовые данные:** ID игр и порядок в данных связки.

**Шаги**

1. Опубликовать сценарий с привязкой игр.
2. Прочитать публичный документ/агрегат связки сценарий–игры.

**Ожидаемый результат:** Порядок в данных совпадает с заданным (A-10).

**Заметки для автоматизации:** Сравнение массива id в порядке из агрегата.

---

### TC-02 — shortDescription для пары сценарий–игра в публичном read

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-01 |
| **Тип** | positive |

**Предусловия:** Для каждой игры в сценарии задан свой `shortDescription`.

**Тестовые данные:** Разные тексты для одной и той же игры в двух сценариях (если поддерживается контентом).

**Шаги**

1. Опубликовать.
2. Запросить публичные данные для сценария A и сценария B.

**Ожидаемый результат:** Для каждой пары сценарий–игра возвращается соответствующий `shortDescription`.

**Заметки для автоматизации:** Проверка денормализованного поля в агрегате списка игр сценария.

---

### TC-03 — Изменение только порядка без смены состава игр

| Поле | Значение |
|------|----------|
| **Приоритет** | P1 |
| **Слой** | integration |
| **Покрывает** | AC-02 |
| **Тип** | positive |

**Предусловия:** Сценарий уже опубликован; клиент может синхронизироваться (имитация FR-M-3 на стороне данных).

**Тестовые данные:** Новый порядок; те же игры.

**Шаги**

1. Обновить только порядок, републиковать агрегат.
2. Прочитать публичные данные и сравнить порядок.

**Ожидаемый результат:** Обновление порядка доступно для последующего чтения клиентом без противоречия политике кэша на стороне клиента (проверка данных).

**Заметки для автоматизации:** Версионирование документа / timestamp для инвалидации кэша — по реализации E2.
