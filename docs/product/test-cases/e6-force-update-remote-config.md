# Тест-кейсы: Принудительное обновление через Remote Config

## Обзор

- Цель: проверить блокировку основного потока при `min_supported_build` выше текущей сборки и при несовместимой `content_schema_version` (A-45, ADR-013).
- Вне scope: серверное принуждение вне клиента.

## Матрица трассировки AC → тест-кейсы

| AC    | TC-ID        | Кратко |
|-------|--------------|--------|
| AC-01 | TC-01, TC-02 | Экран обновления; обход невозможен |
| AC-02 | TC-03        | Ветка по content_schema_version |

## Тест-кейсы

### TC-01 — min_supported_build выше текущей сборки

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | e2e |
| **Покрывает** | AC-01 |
| **Тип** | positive |

**Предусловия:** Remote Config в тестовом проекте: `min_supported_build` > versionCode текущей сборки.

**Шаги**

1. Очистить кэш RC при необходимости, запустить приложение.
2. Дождаться fetch RC.
3. Проверить отображение экрана требования обновления.

**Ожидаемый результат:** Основной контент (витрина) недоступен; пользователь видит CTA в стор (A-45).

**Заметки для автоматизации:** Тестовый Firebase project; не гонять на проде.

---

### TC-02 — Попытка обойти блокировку (back / deep link)

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | e2e |
| **Покрывает** | AC-01 |
| **Тип** | negative |

**Шаги**

1. При активном force-update нажать системную кнопку назад, открыть deep link на сценарий.

**Ожидаемый результат:** Основной контент не становится доступен без обновления (политика продукта — блокировка сохраняется).

---

### TC-03 — content_schema_version выше поддерживаемой клиентом

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-02 |
| **Тип** | positive |

**Предусловия:** В Remote Config или данных задана новая схема; клиент со старым `max_supported_schema`.

**Шаги**

1. Запустить старый клиент.
2. Проверить ту же или согласованную ветку UI обновления (как в стори).

**Ожидаемый результат:** Несовместимость обрабатывается предсказуемо; согласовано с E0 при смене контракта.

## Регресс и смоук

- **Smoke:** TC-04 на каждой сборке; TC-01 на staging при изменении RC.
- **Регресс полный:** TC-01–TC-04 при смене параметров RC или версии схемы E0.

## Допущения

- Fetch RC выполняется при старте или по политике приложения.
