# Тест-кейсы: Crashlytics: отчёты о сбоях

## Обзор

- Цель: проверить появление тестового краша в Crashlytics с читаемым стеком (A-41) и доступность метрик crash-free sessions/users для production.
- Вне scope: алерты Cloud Functions до появления фоновых задач.

## Матрица трассировки AC → тест-кейсы

| AC    | TC-ID        | Кратко |
|-------|--------------|--------|
| AC-01 | TC-01        | Тестовый краш в отчёте |
| AC-02 | TC-02        | Метрики crash-free в консоли |

## Тест-кейсы

### TC-01 — Принудительный тестовый краш (staging / debug)

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | manual-only |
| **Покрывает** | AC-01 |
| **Тип** | positive |

**Предусловия:** Сборка с вызовом тестового краша за флагом; не на проде без согласования.

**Шаги**

1. Вызвать тестовый краш по инструкции SDK.
2. Перезапустить приложение (для отправки отчёта).
3. В Firebase Crashlytics найти новый issue с символизированным стеком.

**Ожидаемый результат:** Отчёт виден; стек читаемый для iOS/Android после dSYM/mapping (A-41).

**Заметки для автоматизации:** Обычно manual-only из-ода характера краша.

---

### TC-02 — Символикация iOS (dSYM)

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-01 |
| **Тип** | positive |

**Шаги**

1. Убедиться, что CI загружает dSYM в Crashlytics для релизных сборок.

**Ожидаемый результат:** Стеки не «смешанные» без имён функций.

### TC-03 — Метрики crash-free в консоли для production

| Поле | Значение |
|------|----------|

| **Слой** | manual-only |
| **Покрывает** | AC-02 |
