# Тест-кейсы: Поля шаринга и SEO для сценария и игры

## Обзор

- Цель: проверить наличие и чтение title/description/OG-полей, уникальность slug и отсутствие «чужого» описания у игры при нескольких сценариях (ED-9).
- Вне scope: полный Universal Links и SSG (E4/E5) — данные готовят контракт.

## Матрица трассировки AC → тест-кейсы

| AC    | TC-ID        | Кратко |
|-------|--------------|--------|
| AC-01 | TC-01        | Поля SEO/share читаются из данных |
| AC-02 | TC-02, TC-03 | Уникальность slug; конфликт отклонён |
| AC-03 | TC-04        | Нет автоподстановки описания из другого сценария |

## Тест-кейсы

### TC-01 — Публичные title, description, OG для сценария и игры

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-01 |
| **Тип** | positive |

**Предусловия:** Опубликованы сценарий и игра с заполненными полями по СТ §4.4.

**Тестовые данные:** Отличимые строки title/description; URL OG-изображения.

**Шаги**

1. Прочитать публичные документы сценария и игры.
2. Сверить наличие полей и их значения с введёнными при импорте.

**Ожидаемый результат:** Клиент или билд может взять метаданные только из данных (FR-M-7, FR-W-2).

**Заметки для автоматизации:** Контрактный тест полей §4.4.

---

### TC-02 — Успешное сохранение уникального slug

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-02 |
| **Тип** | positive |

**Предусловия:** Slug не занят другим объектом того же типа.

**Тестовые данные:** Новый slug.

**Шаги**

1. Сохранить сущность с новым slug до публикации.
2. Убедиться, что slug записан.

**Ожидаемый результат:** Сохранение успешно (ED-8).

**Заметки для автоматизации:** Очистка тестовых slug в teardown.

---

### TC-03 — Отклонение дублирующего slug

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-02 |
| **Тип** | negative |

**Предусловия:** В системе уже есть опубликованный объект с тем же slug.

**Тестовые данные:** Конфликтующий slug.

**Шаги**

1. Попытаться сохранить вторую сущность с тем же slug.
2. Зафиксировать ошибку.

**Ожидаемый результат:** Публикация с дублем slug не проходит; явное сообщение о конфликте.

**Заметки для автоматизации:** Порядок тестов: создать A, затем конфликт B.

---

### TC-04 — Игра в нескольких сценариях: описание не подставляется из «чужого» сценария

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-03 |
| **Тип** | positive |

**Предусловия:** Одна игра связана с двумя сценариями; для страницы/представления игры заданы собственные обязательные SEO-поля (не fallback на текст другого сценария).

**Тестовые данные:** Разные контексты short/SEO при необходимости по контракту.

**Шаги**

1. Опубликовать конфигурацию по ED-9.
2. Запросить публичные SEO-поля игры.

**Ожидаемый результат:** Нет автоподстановки описания из другого сценария; обязательные поля заполнены осмысленно.

**Заметки для автоматизации:** Явная проверка отсутствия поля «borrowed_from_scenario».
