# Тест-кейсы: Обновление контента при наличии сети

## Обзор

- Цель: проверить отсутствие «пустого» главного экрана при фоновом обновлении при наличии кэша и eventual consistency при появлении новой версии документа.
- Вне scope: полная офлайн-логика (US-E2-05).

## Матрица трассировки AC → тест-кейсы

| AC    | TC-ID        | Кратко |
|-------|--------------|--------|
| AC-01 | TC-01, TC-02 | Кэш показывается; нет пустой витрины при обновлении |
| AC-02 | TC-03        | После синхронизации — актуальные данные |

## Тест-кейсы

### TC-01 — Старт приложения с сетью и непустым кэшем

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | e2e |
| **Покрывает** | AC-01 |
| **Тип** | positive |

**Предусловия:** Ранее приложение открывало витрину; кэш Firestore заполнен; сеть включена.

**Шаги**

1. Закрыть и снова открыть приложение (или cold start).
2. Сразу после открытия проверить, что главный экран не пустой (есть карточки из кэша или из сети).
3. При необходимости дождаться индикатора обновления без исчезновения контента на ноль.

**Ожидаемый результат:** Пользователь не видит пустой главный экран из-за задержки сети при наличии кэша (FR-M-3).

**Заметки для автоматизации:** Throttle сети в эмуляторе; таймауты осторожно (флаки).

---

### TC-02 — Медленная сеть: контент из кэша остаётся видимым

| Поле | Значение |
|------|----------|
| **Приоритет** | P1 |
| **Слой** | integration |
| **Покрывает** | AC-01 |
| **Тип** | edge |

**Предусловия:** Инструменты замедления сети (Charles / эмулятор).

**Шаги**

1. Включить сильный throttle.
2. Открыть главный экран с заполненным кэшем.

**Ожидаемый результат:** Список не исчезает; при появлении новых данных — плавное обновление без «мигания» в пустоту.

---

### TC-03 — Обновление документа на сервере подтягивается клиентом

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-02 |
| **Тип** | positive |

**Предусловия:** Изменён заголовок сценария на сервере в тестовом проекте.

**Шаги**

1. Открыть экран сценария со старым кэшем.
2. Инициировать обновление (перезапуск, pull-to-refresh, возврат на экран — по реализации).
3. Проверить новый заголовок.

**Ожидаемый результат:** В конечном счёте отображается актуальная версия после синхронизации (A-20).

**Заметки для автоматизации:** Ожидание snapshot listener с таймаутом.
