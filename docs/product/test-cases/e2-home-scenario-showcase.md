# Тест-кейсы: Главный экран: витрина сценариев

## Обзор

- Цель: проверить загрузку витрины из публичного агрегата, соответствие порядка и состава серверу, отображение названия и опционального подзаголовка, переход на экран сценария.
- Вне scope: группы смысла (E7), push (E3).

## Матрица трассировки AC → тест-кейсы

| AC    | TC-ID        | Кратко |
|-------|--------------|--------|
| AC-01 | TC-01, TC-02 | Порядок и состав как на сервере |
| AC-02 | TC-03        | Название и подзаголовок из данных |

## Тест-кейсы

### TC-01 — Список сценариев и порядок совпадают с home_feed

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | e2e |
| **Покрывает** | AC-01 |
| **Тип** | positive |

**Предусловия:** В тестовом проекте известен эталонный порядок id сценариев в `home_feed`; сеть доступна.

**Тестовые данные:** Эталонный JSON или экспорт из Firestore.

**Шаги**

1. Открыть приложение на главном экране.
2. Считать порядок карточек/элементов витрины (текст или `data-testid`/семантика).
3. Сравнить с эталоном.

**Ожидаемый результат:** Порядок и набор сценариев совпадают с сервером (FR-M-1).

**Заметки для автоматизации:** Стабильный тестовый проект; моки Firestore для widget-тестов без сети.

---

### TC-02 — После изменения витрины на сервере UI обновляется

| Поле | Значение |
|------|----------|
| **Приоритет** | P1 |
| **Слой** | integration |
| **Покрывает** | AC-01 |
| **Тип** | positive |

**Предусловия:** Возможность изменить данные витрины в тестовом окружении и перезапустить приложение или pull-to-refresh.

**Тестовые данные:** Добавление/скрытие сценария на витрине.

**Шаги**

1. Зафиксировать список на главном экране.
2. Изменить витрину на сервере, обновить контент в приложении (см. E2-04).
3. Сверить новый список.

**Ожидаемый результат:** Состав витрины соответствует новым данным.

**Заметки для автоматизации:** Частично manual-only если нет API для смены контента в CI.

---

### TC-03 — Отображение названия и опционального подзаголовка

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | widget |
| **Покрывает** | AC-02 |
| **Тип** | positive |

**Предусловия:** У одного сценария задан подзаголовок, у другого — нет.

**Тестовые данные:** Два элемента витрины из фикстуры.

**Шаги**

1. Открыть главный экран.
2. Найти карточку с подзаголовком — проверить текст.
3. Найти карточку без подзаголовка — проверить отсутствие лишнего placeholder или дубля заголовка.

**Ожидаемый результат:** Название всегда видно; подзаголовок только если есть в данных.

**Заметки для автоматизации:** `find.text` / golden при фиксированной теме.

### TC-04 — Тап по карточке открывает экран сценария

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | e2e |
| **Покрывает** | AC-01 (навигация) |
| **Тип** | positive |

**Предусловия:** Известен id сценария первой карточки.

**Шаги**

1. Тапнуть по первой карточке витрины.
2. Проверить, что открыт экран сценария с тем же сценарием (заголовок/id).

**Ожидаемый результат:** Навигация на корректный сценарий.

**Заметки для автоматизации:** Связь с US-E6-02 (source=home) при проверке аналитики.
