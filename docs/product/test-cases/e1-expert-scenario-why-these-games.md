# Тест-кейсы: Сценарий с «почему эти игры подходят» и витриной

## Обзор

- Цель: проверить обязательность и формат `whyTheseGames` при publish и формирование `home_feed`/агрегата для главного экрана без релиза МП.
- Вне scope: группы смысла и «Сценарии прошлого» (E7).

## Матрица трассировки AC → тест-кейсы

| AC    | TC-ID        | Кратко |
|-------|--------------|--------|
| AC-01 | TC-01, TC-02 | whyTheseGames обязателен; plain text и \\n |
| AC-02 | TC-03, TC-04 | Витрина и порядок в агрегате; главный экран из данных |

## Тест-кейсы

### TC-01 — Publish без whyTheseGames запрещён

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-01 |
| **Тип** | negative |

**Предусловия:** Сценарий в черновике; остальные обязательные поля заполнены.

**Тестовые данные:** Пустое или отсутствующее поле `whyTheseGames`.

**Шаги**

1. Выполнить операцию publish.
2. Зафиксировать ошибку валидации/пайплайна.

**Ожидаемый результат:** Публикация не проходит; явное требование заполнить `whyTheseGames`.

**Заметки для автоматизации:** Контрактная проверка в скрипте импорта.

---

### TC-02 — Сохранение whyTheseGames с переносами строк

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-01 |
| **Тип** | positive |

**Предусловия:** Текст plain text с символами `\n`.

**Тестовые данные:** Многострочный `whyTheseGames`.

**Шаги**

1. Опубликовать сценарий с многострочным текстом.
2. Прочитать из Firestore публичное представление и сравнить сохранённые переносы.

**Ожидаемый результат:** Текст сохранён как plain text; переносы не потеряны (A-4a).

**Заметки для автоматизации:** Сравнение escape-последовательностей в JSON.

---

### TC-03 — home_feed содержит сценарий с признаками витрины и порядком

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-02 |
| **Тип** | positive |

**Предусловия:** Заданы признак витрины и порядок в данных сценария/агрегата.

**Тестовые данные:** Несколько сценариев с разным `order`.

**Шаги**

1. После публикации прочитать `home_feed` (или эквивалент).
2. Проверить порядок элементов и флаги отображения на витрине.

**Ожидаемый результат:** Список на главном экране МП может быть построен только из агрегата без изменения кода приложения.

**Заметки для автоматизации:** Snapshot `home_feed` в CI.

---

### TC-04 — Изменение порядка на витрине отражается в агрегате

| Поле | Значение |
|------|----------|
| **Приоритет** | P1 |
| **Слой** | integration |
| **Покрывает** | AC-02 |
| **Тип** | positive |

**Предусловия:** Два опубликованных сценария на витрине.

**Тестовые данные:** Новый порядок sort key.

**Шаги**

1. Обновить только порядок витрины и републиковать/обновить агрегат.
2. Перечитать `home_feed`.

**Ожидаемый результат:** Порядок в агрегате соответствует новым данным.

**Заметки для автоматизации:** Зависит от триггера обновления агрегата (задокументировать).
