# Тест-кейсы: Не больше одного push в сутки в 11:00 МСК

## Обзор

- Цель: проверить расписание отправки в 11:00 МСК, не более одного сообщения на topic за сутки и выбор последней новинки при нескольких событиях (A-7a, A-32); payload с текстом из данных (ED-11).
- Вне scope: минимальный релиз без push — полная приёмка при включении продукта push.

## Матрица трассировки AC → тест-кейсы

| AC    | TC-ID        | Кратко |
|-------|--------------|--------|
| AC-01 | TC-01        | Одно сообщение за сутки на topic |
| AC-02 | TC-02        | Несколько новинок → последняя в payload |
| AC-03 | TC-03        | Текст из конфига/данных, не только хардкод |

## Тест-кейсы

### TC-01 — Один push за календарные сутки при нескольких событиях в очереди

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-01 |
| **Тип** | positive |

**Предусловия:** Staging; Cloud Scheduler переведён на тестовое время или используется ручной триггер с той же логикой; в очереди несколько новых сценариев за день.

**Шаги**

1. Накопить ≥2 события новинки за сутки (E1-05).
2. Дождаться окна отправки 11:00 МСК (или эмуляции).
3. Подсчитать количество FCM-сообщений на topic за сутки на тестовом подписчике.

**Ожидаемый результат:** Не более одного сообщения на topic за календарные сутки (A-7a).

**Заметки для автоматизации:** Тестовый clock / feature flag времени; логи Cloud Functions.

---

### TC-02 — При нескольких новинках в payload — последний опубликованный сценарий

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-02 |
| **Тип** | positive |

**Предусловия:** За день опубликованы сценарии A затем B (известные timestamp/id).

**Шаги**

1. После отправки прочитать payload тестового сообщения (логи, тестовый клиент).
2. Сверить `scenarioId` с последним опубликованным.

**Ожидаемый результат:** В уведомлении ссылка/идентификатор последней новинки (A-32, use-cases).

---

### TC-03 — Заголовок/тело из Remote Config / Firestore

| Поле | Значение |
|------|----------|
| **Приоритет** | P1 |
| **Слой** | integration |
| **Покрывает** | AC-03 |
| **Тип** | positive |

**Предусловия:** В конфиге заданы нестандартные строки для заголовка/тела.

**Шаги**

1. Изменить текст в источнике (ED-11).
2. Выполнить отправку (или дождаться следующего окна).
3. Проверить текст на устройстве.

**Ожидаемый результат:** Текст соответствует данным/конфигу, а не только константе в коде.

## Регресс и смоук

- **Smoke:** TC-01, TC-02 (на staging с push).
- **Регресс полный:** все TC при изменении Scheduler или очереди E1-05.

## Допущения

- Таймзона МСК корректно задана в Scheduler (UTC offset).
