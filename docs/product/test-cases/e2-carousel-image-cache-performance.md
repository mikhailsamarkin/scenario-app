# Тест-кейсы: Производительность карусели и кэш изображений

## Обзор

- Цель: проверить повторное использование дискового кэша изображений карусели и отсутствие систематических фризов при листании на целевых устройствах.
- Вне scope: оптимизация всего приложения вне карусели.

## Матрица трассировки AC → тест-кейсы

| AC    | TC-ID        | Кратко |
|-------|--------------|--------|
| AC-01 | TC-01        | Повторное открытие — из кэша диска |
| AC-02 | TC-02        | Листание без систематических фризов |

## Тест-кейсы

### TC-01 — Повторное открытие игры: изображения из кэша

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-01 |
| **Тип** | positive |

**Предусловия:** Карусель с несколькими изображениями; первый визит онлайн для загрузки.

**Шаги**

1. Онлайн открыть экран игры, пролистать все слайды.
2. Закрыть экран, снова открыть ту же игру (в идеале офлайн или с отключённой сетью для проверки кэша).
3. Проверить по логам/инструментам (или времени появления), что изображения не грузятся заново с сети при наличии кэша в пределах лимита диска (A-21a).

**Ожидаемый результат:** Повторное использование локального кэша; лимит диска не превышен критически (мониторинг размера кэша).

**Заметки для автоматизации:** Логи HTTP-клиента (0 запросов при офлайн); зависит от библиотеки (ED-6/ED-13).

---

### TC-02 — Листание карусели: плавность на целевом устройстве

| Поле | Значение |
|------|----------|
| **Приоритет** | P1 |
| **Слой** | manual-only |
| **Покрывает** | AC-02 |
| **Тип** | positive |

**Предусловия:** Устройство из матрицы приёмки; типичный набор слайдов.

**Шаги**

1. Открыть экран игры.
2. Быстро листать карусель вперёд-назад ~20 раз.
3. По чеклисту QA зафиксировать отсутствие систематических подвисаний (NFR-SR-6).

**Ожидаемый результат:** Нет устойчивых фризов; при редких просадках — зафиксировать устройство и шаги для багрепорта.

**Заметки для автоматизации:** FPS/perf overlay в профилировщике — опционально; субъективная часть остаётся manual-only или пороги в CI по профайлеру.

---

### TC-03 — Лимит диска кэша: вытеснение старых изображений

| Поле | Значение |
|------|----------|
| **Приоритет** | P2 |
| **Слой** | integration |
| **Покрывает** | AC-01 |
| **Тип** | edge |

**Предусловия:** Возможность заполнить кэш большим числом игр или настроить низкий лимит в dev.

**Шаги**

1. Открыть много разных игр с тяжёлыми каруселями.
2. Вернуться к первой игре и проверить повторную загрузку при необходимости.

**Ожидаемый результат:** Кэш не растёт бесконечно; поведение предсказуемо (A-21a).

## Регресс и смоук

- **Smoke:** TC-01 (по возможности автоматизированный).
- **Регресс полный:** TC-01–TC-03 при смене библиотеки кэша или экрана игры (E2-03).
