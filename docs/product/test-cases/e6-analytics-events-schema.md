# Тест-кейсы: Именованная схема событий аналитики в МП

## Обзор

- Цель: проверить соблюдение реестра имён и параметров событий (A-35, ED-14) и наличие базовых событий навигации по экранам (FR-M-6).
- Вне scope: детальные source сценария (E6-02), block_view (E6-03).

## Матрица трассировки AC → тест-кейсы

| AC    | TC-ID        | Кратко |
|-------|--------------|--------|
| AC-01 | TC-01, TC-02 | Только реестровые имена |
| AC-02 | TC-03        | События при переходах по основным экранам |

## Тест-кейсы

### TC-01 — Запрет неизвестного имени события в коде

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | unit |
| **Покрывает** | AC-01 |
| **Тип** | negative |

**Предусловия:** Реестр событий в коде или JSON; lint/тест запрещает произвольные строки.

**Шаги**

1. Попытаться залогировать событие с именем вне реестра в тесте — ожидать падение теста или ошибку компиляции.

**Ожидаемый результат:** Произвольные имена не проходят (A-35).

**Заметки для автоматизации:** Enum sealed class + static analysis.

---

### TC-02 — Событие из реестра: параметры соответствуют схеме

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | unit |
| **Покрывает** | AC-01 |
| **Тип** | positive |

**Шаги**

1. Для каждого зарегистрированного события проверить обязательные параметры (contract test).

**Ожидаемый результат:** Ни одно событие не отправляется с неполным набором полей.

---

### TC-03 — Типичная сессия: витрина → сценарий → игра

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-02 |
| **Тип** | positive |

**Предусловия:** DebugView или тестовый Analytics sink.

**Шаги**

1. Пройти путь: главный → сценарий → игра.
2. Убедиться, что для каждого шага отправлены ожидаемые события навигации/просмотра по FR-M-6.

**Ожидаемый результат:** События присутствуют и именованы по реестру.

**Заметки для автоматизации:** Fake Analytics с записью вызовов.

---
