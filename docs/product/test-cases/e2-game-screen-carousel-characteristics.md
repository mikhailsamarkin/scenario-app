# Тест-кейсы: Экран игры: карусель, характеристики, краткое описание в контексте сценария

## Обзор

- Цель: проверить карусель (типы, порядок, alt), четыре enum-характеристики и `shortDescription` для пары сценарий–игра.
- Вне scope: производительность карусели (US-E2-06).

## Матрица трассировки AC → тест-кейсы

| AC    | TC-ID        | Кратко |
|-------|--------------|--------|
| AC-01 | TC-01, TC-02 | Карусель и alt |
| AC-02 | TC-03        | Четыре характеристики из контракта |
| AC-03 | TC-04        | shortDescription в контексте сценария |

## Тест-кейсы

### TC-01 — Карусель: типы слайдов и порядок

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | e2e |
| **Покрывает** | AC-01 |
| **Тип** | positive |

**Предусловия:** Игра открыта из сценария; в данных несколько слайдов с известными типами.

**Шаги**

1. Открыть экран игры.
2. Листать карусель и сверить порядок и типы слайдов с данными (лог/фикстура).
3. Для слайдов с изображениями проверить наличие alt в accessibility / семантике (где задано в данных).

**Ожидаемый результат:** Карусель соответствует CR-5; alt присутствует где задано.

**Заметки для автоматизации:** `Semantics`/`label` в Flutter; скриншоты опционально.

### TC-03 — Четыре характеристики отображаются по enum

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | widget |
| **Покрывает** | AC-02 |
| **Тип** | positive |

**Предусловия:** Игра с четырьмя заполненными характеристиками из контракта.

**Шаги**

1. Открыть экран игры.
2. Проверить наличие ровно четырёх блоков характеристик и соответствие подписей/иконок маппингу enum (CR-4.1).

### TC-04 — shortDescription зависит от сценария входа

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | e2e |
| **Покрывает** | AC-03 |
| **Тип** | positive |

**Предусловия:** Одна игра в двух сценариях с разным `shortDescription` в связке.

**Шаги**

1. Из сценария A открыть игру — запомнить краткое описание.
2. Вернуться, из сценария B открыть ту же игру.

**Ожидаемый результат:** Описание соответствует связке сценарий–игра для текущего входа (FR-M-2); не подставляется из другого сценария (ED-9 на данных).

**Заметки для автоматизации:** Передача `scenarioId` в маршрут обязательна.
