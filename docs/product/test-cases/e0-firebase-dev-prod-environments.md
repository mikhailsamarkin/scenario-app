# Тест-кейсы: Окружения Firebase dev/staging и production

## Обзор

- Цель: убедиться, что существуют отдельные проекты/окружения от production для тестов и что секреты не хранятся в git.
- Вне scope: полный CI/CD всех каналов, если не требуется для приёмки окружений.

## Матрица трассировки AC → тест-кейсы

| AC    | TC-ID        | Кратко |
|-------|--------------|--------|
| AC-01 | TC-01, TC-02 | Отдельное окружение; клиент не бьёт прод при тесте |
| AC-02 | TC-03, TC-04 | Секреты не в репозитории; конфиг через env |

## Тест-кейсы

### TC-01 — Наличие непродакшен Firebase-проекта

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | manual-only |
| **Покрывает** | AC-01 |
| **Тип** | positive |

**Предусловия:** Доступ к консоли Firebase/Google Cloud.

**Тестовые данные:** Идентификаторы проектов dev/staging и production.

**Шаги**

1. Открыть список проектов Firebase для организации.
2. Убедиться, что для разработки/стейджинга указаны отдельные project id отличные от production.

**Ожидаемый результат:** Существует как минимум одно непродакшен-окружение согласно политике A-43.

**Заметки для автоматизации:** Проверка через IaC/скрипт с read-only API; иначе чеклист релиза.

---

### TC-02 — Клиентская сборка указывает непродакшен-проект для dev

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-01 |
| **Тип** | positive |

**Предусловия:** Собрана dev-сборка с переменными окружения для dev-проекта.

**Тестовые данные:** `google-services.json` / `GoogleService-Info.plist` из CI-секретов, не из git.

**Шаги**

1. Запустить приложение в dev-режиме.
2. Убедиться по логам/аналитике/Firebase DebugView, что подключён dev project id (не production).

**Ожидаемый результат:** Публикация и клиент в тесте не затрагивают production-данные.

**Заметки для автоматизации:** Smoke job в CI с подстановкой env из secrets.

---

### TC-03 — Отсутствие ключей сервисных аккаунтов в git

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-02 |
| **Тип** | negative |

**Предусловия:** Клонирован репозиторий; настроен поиск секретов (gitleaks / git-secrets).

**Тестовые данные:** нет

**Шаги**

1. Запустить сканер секретов по истории ветки `main` (или политике команды).
2. Проверить `.gitignore` на шаблоны ключей Firebase/GCP.

**Ожидаемый результат:** Совпадений с JSON-ключами SA и приватными ключами нет; при ложных срабатываниях — исключения документированы.

**Заметки для автоматизации:** Обязательный шаг в CI (P0 gate).

---

### TC-04 — Конфигурация CI через переменные окружения

| Поле | Значение |
|------|----------|
| **Приоритет** | P1 |
| **Слой** | integration |
| **Покрывает** | AC-02 |
| **Тип** | positive |

**Предусловия:** Документирован способ указания `FIREBASE_*` / `GOOGLE_APPLICATION_CREDENTIALS` для скриптов.

**Тестовые данные:** Тестовый pipeline с секретами из хранилища CI.

**Шаги**

1. Запустить workflow импорта/деплоя с подставленными секретами из CI.
2. Убедиться, что в логах и артефактах нет вывода полного ключа.

**Ожидаемый результат:** Секреты только из vault/secrets store, не из репозитория.

**Заметки для автоматизации:** Маскирование секретов в логах — настройка CI.
