# Тест-кейсы: Предсказуемый билд SSG: бюджет запросов к Firestore

## Обзор

- Цель: убедиться, что при полной генерации страниц число чтений Firestore на URL укладывается в ориентир A-10b и что полный rebuild запускается согласованным workflow (ED-10).
- Вне scope: ISR по расписанию.

## Матрица трассировки AC → тест-кейсы

| AC    | TC-ID        | Кратко |
|-------|--------------|--------|
| AC-01 | TC-01        | Измерение чтений/URL в CI |
| AC-02 | TC-02        | workflow_dispatch → полный rebuild |

## Тест-кейсы

### TC-01 — Регрессия бюджета чтений при билде

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | integration |
| **Покрывает** | AC-01 |
| **Тип** | positive |

**Предусловия:** В CI включён сбор метрик чтений Firestore за билд; известен порог A-10b для команды.

**Шаги**

1. Запустить полный билд SSG на типичном объёме контента.
2. Собрать отчёт: среднее и пиковое число чтений на сгенерированный URL.
3. Сравнить с порогом.

**Ожидаемый результат:** Метрики не превышают согласованный ориентир; при превышении — падает job (policy команды).

**Заметки для автоматизации:** Хук в Next.js data layer; артефакт `firestore-reads.json` в CI.

---

### TC-02 — Ручной запуск workflow полного rebuild

| Поле | Значение |
|------|----------|
| **Приоритет** | P0 |
| **Слой** | manual-only |
| **Покрывает** | AC-02 |
| **Тип** | positive |

**Предусловия:** Настроен GitHub Actions (или аналог) с `workflow_dispatch` по ED-10.

**Шаги**

1. Запустить workflow вручную после обновления контента.
2. Убедиться, что выполнен полный rebuild, а не частичный без согласования.

**Ожидаемый результат:** Сайт обновлён предсказуемо; документация для команды актуальна.

| Поле | Значение |
|------|----------|
| **Приоритет** | P2 |
