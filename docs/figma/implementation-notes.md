# Заметки для реализации редизайна

Собрано при изучении макетов 2026-09-08. См. [README.md](README.md) для состава.

## Критический путь

1. **Контракт и данные (блокирует home и экран сценария)**
   - категория сценария: контракт E0 → импорт E1 → агрегаты dev/prod;
   - решение по секциям home (вариант A/B, см. [data-changes.md](data-changes.md)).
2. **Дизайн-система**
   - тема приложения: палитра + типографика из [design-tokens.md](../design-tokens.md)
     (после снятия точных значений из Figma);
   - общие виджеты: hero-блок (фото + затемнение + капс-категория + serif-заголовок),
     точки-индикаторы, капс-заголовок секции, карточка на лавандовом, кнопки.
3. **Экраны** (по зависимости, а не по номеру):
   - онбординг (не зависит от данных; 3 шага вместо 4 — см.
     [screens/onboarding.md](screens/onboarding.md));
   - игра (данные есть, только UI);
   - сценарий (ждёт категорию);
   - home (ждёт категорию + решение по секциям).

## Что сохранить при переделке (не сломать)

- Функциональные требования и AC реализованных сторей: офлайн-состояния,
  `block_view`-трекинг (kBlockScenarioWhy/kBlockScenarioGames, home), аналитика
  (scenario_open по source), deep links, force update, «О приложении».
- Инжектируемые колбэки (`onOpenScenario`, `onOpenGame`, `onShare`) и
  тестируемость — текущие тесты (19 файлов) частично проверяют структуру
  виджетов; при смене `ListTile` → карточки тесты обновить.
- Контракт `home_feed`/`scenario_public`/`game_public` — изменения только
  добавлением поля категории (обратная совместимость с кэшем).

## Скелет нового общего кода (предложение)

- `lib/design/` (или `lib/ui/theme/`): `AppColors`, `AppTypography`,
  `AppTheme` (light-only? тёмный онбординг и светлый контент могут жить в
  одной теме через явные цвета, а не ThemeData.dark).
- `lib/ui/widgets/`: `HeroHeader`, `SectionCapsHeader`, `DotsIndicator`,
  `ScenarioCardLarge` (витрина), `ScenarioCardCompact` (секции),
  `GameListTile` (лавандовая карточка с чипсами), `CharacteristicTile` (2×2).

## Открытые вопросы (собрано со всех экранов)

1. **Точные токены**: hex-цвета, гарнитуры (serif для заголовков — какой?),
   размеры/отступы — снять Dev Mode'ом в Figma. Текущие значения в
   [design-tokens.md](../design-tokens.md) — приближения по скриншотам.
2. **Ассеты**: иллюстрации онбординга (на фреймах 2 и 3 область пуста —
   будут ли коллажи как на фрейме 1?), формат экспорта (PNG? масштабы 1x/2x/3x),
   куда складывать (Supabase Storage? бандл приложения?).
3. **Кнопка «Назад» на экране игры**: дублирует системную навигацию —
   уточнить у дизайнера назначение (возможно «К сценарию»).
4. **Категории**: список, терминология (совпадают ли с «группами смысла» E7),
   обязательность, кто управляет (см. [data-changes.md](data-changes.md)).
5. **Обрезка фрейма home**: что ниже «С детьми» — не видно; уточнить полный
   состав home (футер? таб-бар? сколько секций?).
6. **Порядок шагов онбординга vs push-подписка US-E3-02**: подписка на topic
   при «Разрешить уведомления» сохраняется; поведение «Начать без уведомлений» =
   текущий отказ (не блокирует).
