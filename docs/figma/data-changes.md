# Изменения данных, которые требует редизайн

Редизайн — в основном presentation-слой, но одна тема требует изменений
контракта и пайплайна: **категории сценариев**.

## 1. Категория сценария

Где видна в макетах:

- **home**: секции-ленты по категориям («Вдвоём», «С детьми»…) и капс-надпись
  на карточках («ВДВОЁМ», «С ДЕТЬМИ»);
- **экран сценария**: капс-надпись в hero («ВДВОЁМ»).

Сейчас: у `ScenarioCard` и `ScenarioPublic` (`lib/data/contract/models.dart`)
поля категории нет. В E1 есть отдельное понятие «группы смысла»
(semantic groups, US-E7-01 — не реализовано) — возможно, категории в макетах
и есть эти группы смысла; нужно сверить термины (см. открытые вопросы).

Требуемые изменения:

1. Контракт E0: поле категории (id + display-название?) в `ScenarioCard` /
   `ScenarioPublic` (или отдельный справочник категорий).
2. Пайплайн E1: категория в исходных данных сценария, валидация
   (обязательность, допустимые значения), импорт в агрегаты.
3. `home_feed`: либо секции как структура агрегата, либо клиентская
   группировка (решение ниже).

## 2. Секции home_feed: два варианта

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Секции в агрегате: `home_feed.sections: [{categoryId, title, scenarioCards[]}]` + витрина | порядок/состав секций управляются с сервера (как AC-01 SP-E2-01), клиент тупой | дороже: изменение схемы, импорта, валидаторов |
| B. Клиентская группировка: в `home_feed` остаётся витрина + полный список, клиент группирует по `scenario.category` | контракт почти не меняется (только поле категории) | порядок секций зашит в код; «пустые» категории обрабатывать на клиенте |

Рекомендация — вариант B для первой итерации (дешевле, категория всё равно
нужна для экрана сценария), вариант A — если потребуется независимое от
релизов приложения управление порядком секций.

## 3. «Редакторский выбор» (подпись у витрины)

В макете у витрины подпись «Редакторский выбор». Достаточно статичной
подписи (это просто название блока) — отдельный признак `editorsPick`
у карточки **не требуется**, если витрина целиком считается редакторским
выбором (так и задумано по E1: состав витрины — ручной). Зафиксировать
в спеке, что подпись — константа UI.

## 4. Что НЕ меняется

- Чипсы характеристик (сценарий) — `playersHint`/`durationBucket`/`rulesComplexity`
  уже в `ScenarioGameRef`.
- Карточка 2×2 (игра) — те же поля из `GamePublic`.
- Бейдж на фото карусели — `Slide.caption` уже в контракте.
- Тексты онбординга — не данные, а UI-константы.

3. Вариант A или B для секций home (см. выше).
